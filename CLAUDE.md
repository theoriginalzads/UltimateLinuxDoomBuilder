# Ultimate Linux Doom Builder (ULDB)

An unofficial native Linux fork of [Ultimate Doom Builder](https://github.com/UltimateDoomBuilder/UltimateDoomBuilder): .NET 10 + Avalonia 12 instead of Mono + WinForms. It's a GZDoom/UZDoom-only map editor. The port is AI-coded, and this is disclosed publicly.

## Read first, every session

1. `docs/ULDB-Plan.md`: the plan and every decision made so far. Section 0 has the background.
2. `docs/progress.md`: where the work is now, and what's next.
3. `docs/architecture.md`: how the fork is built (compat layer, single Builder assembly, UI placeholders, hosted rendering, compilers).
4. `docs/port-map.md`: which upstream WinForms file maps to which Avalonia file.

## Rules

- **Don't move, rename or delete upstream files.** New code goes in new places: `Source/ULDB/`, `tools/`, `docs/`. Exclude WinForms files from new projects with globs instead. This keeps merges from upstream UDB releases clean.
- **Prefer the compat layer over editing upstream code.** If upstream uses a WinForms or `System.Drawing` API, add it to `Source/ULDB/Compat`. Edit an upstream file only when shimming would be contorted, then:
  - wrap the edit in `#if ULDB … #else <original> #endif`
  - **preserve CRLF line endings** (most upstream files use them; read and write with `newline=''` in Python)
  - list it in `docs/upstream-edits.md`
- **Leave upstream project files alone** (`Builder.sln`, `BuilderMono.sln`, `*.csproj`). The fork builds from its own solution and project files.
- **Port windows one-to-one:** same class names and event-handler names, with the `*.Designer.cs` layout rebuilt as `.axaml`. Record each port in `docs/port-map.md`.
- **Hide, don't delete:** non-GZDoom/UZDoom targets are hidden in the UI through one fork-owned filter. Record each hidden item in `docs/scope-hidden.md`.
- **UI changes:** the UI should stay familiar to UDB users. Record any moved or changed UI in `docs/ux-changes.md`. Get the user's sign-off (with a screenshot) before major layout changes.
- **Branding:** user-visible name strings come from one `Branding` class. Internal namespaces and assembly names stay unchanged.
- **Git:** one branch per phase (`phase-N/...`), small commits, and push often (cloud containers are temporary). Every AI-authored commit carries the `Co-Authored-By: Claude` trailer.
- **Update `docs/progress.md`** at the end of each work session.

## Build and run

```sh
git submodule update --init            # once: compiler/node builder sources (tools/compilers/src)
dotnet build Builder.Linux.sln          # ULDB.Compat + Builder + libBuilderNative.so + compilers (-p:UldbArch=znver4 optional)
dotnet test Builder.Linux.sln           # upstream's tests + ULDB's (generates tests/maps if missing; needs python3)
python3 tools/uistubgen/prune.py        # regenerate UI placeholders; prints remaining upstream errors
```

Reference (upstream Mono) build, on a machine with Mono's `msbuild` (Arch/CachyOS: `mono mono-msbuild`):

```sh
make            # builds Build/Builder.exe and Build/libBuilderNative.so
cd Build && ./builder
```

Test maps (GZDoom/UZDoom UDMF) are generated by `tools/testmaps/make_testmaps.py`. Output goes to `tests/maps/`.

## Environment notes

- **Cloud container (Ubuntu 24.04):**
  - Install .NET 10 with `apt-get install dotnet-sdk-10.0`. The `dot.net` install script is blocked by the proxy.
  - The upstream Mono build does **not** work here: there's no `msbuild`, `dotnet msbuild` fails on the WinForms `.resx` files, and `xbuild` is too old. Use the user's machine for the reference build.
  - `Xvfb` plus Mesa (llvmpipe) is available for headless smoke tests.
  - Freedoom IWADs: `apt-get install freedoom` puts them in `/usr/share/games/doom/`.
  - GitHub release downloads are blocked by the proxy; `git clone` works.
- **User's machine:** CachyOS with KDE Plasma, Ryzen 9 9950X (Zen 4).
